COMPONENTES DEL SISTEMA
------------------------------------------------------------

MS1 — Ventas POS (Punto de Venta Fisico)
https://github.com/frani3/Grupo-Cordillera-E2/tree/rama-merge/proyecto-evaluacion-2/ms1-pos
Patron GoF: Singleton (Holder Pattern)
Descripcion: Recibe transacciones de ventas en tiendas fisicas via POST,
las valida, limpia y almacena en una unica lista thread-safe en memoria
(CopyOnWriteArrayList). Garantiza una sola instancia del repositorio
entre todos los threads del microservicio. Puerto 8081.

MS2 — Ventas Online (Canal E-commerce)
https://github.com/frani3/Grupo-Cordillera-E2/tree/rama-merge/proyecto-evaluacion-2/ms2-online
Patron GoF: Singleton (Holder Pattern)
Descripcion: Recibe transacciones de ventas del canal online (web, app,
marketplace) via POST, las valida, limpia y almacena en memoria con el
mismo Holder Pattern que MS1. Dominio independiente de MS1, sin
dependencias cruzadas. Puerto 8083.

ORQ-SERVICE — Servicio Orquestador
https://github.com/frani3/Grupo-Cordillera-E2/tree/rama-merge/proyecto-evaluacion-2/orq-service
Patron GoF: Strategy
Descripcion: Consulta MS1 y MS2 en paralelo (CompletableFuture),
consolida los datos de ambos canales y aplica el algoritmo de
procesamiento seleccionado en runtime: batch (resumen total y suma de
montos), stream (ultima transaccion por canal), cache (listado con
metodo de pago). El algoritmo se cambia via parametro ?strategy= sin
modificar el codigo. Puerto 8082.

BFF-SERVICE — Backend for Frontend
https://github.com/frani3/Grupo-Cordillera-E2/tree/rama-merge/proyecto-evaluacion-2/bff-service
Patron GoF: Proxy (Proteccion + Auditoria + Errores)
Descripcion: Intercepta todos los requests del cliente antes de
delegarlos al orquestador. Valida el token Bearer (401 si ausente o
invalido), registra cada operacion con timestamp en el audit log y
captura excepciones del servicio real sin exponer stack traces al
cliente. El Controller nunca sabe si habla con el servicio real o un
intermediario. Puerto 8080.

FRONTEND-APP — Cliente HTTP (Node.js)
https://github.com/frani3/Grupo-Cordillera-E2/tree/rama-merge/proyecto-evaluacion-2/frontend-app
Patron GoF: Factory Method
Descripcion: Servidor Express que actua como cliente del BFF.
ApiServiceFactory.create("data", "production") instancia el cliente
HTTP con la URL y timeout correctos segun el entorno (development /
production / test) sin que los componentes conozcan las URLs concretas.
Extensible via register() sin modificar la factory existente. Puerto 3000.

INFRAESTRUCTURA
------------------------------------------------------------

Docker Compose (orquestacion completa)
https://github.com/frani3/Grupo-Cordillera-E2/blob/rama-merge/proyecto-evaluacion-2/docker-compose.yml
Levanta todos los servicios en la red interna cordillera-net junto con
MySQL 8.0 y RabbitMQ 3. Configura las URLs entre servicios via variables
de entorno (DATA_MS_URL, DATA_MS2_URL, ORQ_SERVICE_URL, BFF_URL).
